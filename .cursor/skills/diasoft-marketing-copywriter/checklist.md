# Чек-лист и практики B2B/fintech-маркетинга

## A. Предпубликационный чек-лист (пройти перед выдачей текста)

**Факты**
- [ ] Каждая цифра, дата, номер акта есть в брифе или помечена `[уточнить]`.
- [ ] Статус проекта в заголовке = статусу в тексте (ОПЭ ≠ промышленная эксплуатация).
- [ ] Регуляторные ссылки в форме «указание Банка России от ДД.ММ.ГГГГ №…» и вынесены в список для юристов.
- [ ] Названия продуктов по номенклатуре Digital Q, должности спикеров — дословно из брифа.

**Структура**
- [ ] Заголовок — одно предложение, без двоеточия и цифр, ≤ 90 знаков.
- [ ] Лид отвечает на «кто, что, когда, на чем, зачем»; журналист может опубликовать один лид.
- [ ] Главный измеримый результат — в первой трети текста.
- [ ] Основное решение и дополнительные сервисы — разные блоки.
- [ ] Финал: сопровождение / переход в промэксплуатацию / планы развития.

**Цитаты**
- [ ] У каждой цитаты своя функция (приемка / суть проекта / доп. сервис); цитаты нельзя поменять местами без потери смысла.
- [ ] Ни один факт не повторяется в тексте и цитате дословно; ключевой показатель — один раз, у заказчика.
- [ ] В цитатах нет перечислений систем и продуктов — они в основном тексте.
- [ ] Цитата «Диасофт» не начинается с внутренней оптики («ключевой для нашего направления проект»); начинается со значения для рынка/заказчика.
- [ ] Нет утверждений, которые спикер не сможет подтвердить.

**Тон и язык**
- [ ] Прошлое заказчика описано нейтрально; нет слов «ошибки», «штрафы», «ручной хаос».
- [ ] Нет оценочных эпитетов (революционный, уникальный, лучший).
- [ ] «ИТ», кавычки «», тире «–» перед атрибуцией; единообразие M2M/М2М, НРД раскрыт при первом упоминании.
- [ ] Объем 350–650 слов для релиза; абзацы 2–5 предложений.

**Сопровождение**
- [ ] Список изменений (если правка) и список открытых вопросов сторонам.
- [ ] Отмечено, какие блоки добавляют стороны: «О компании», контакты.

## B. Современные практики B2B / fintech-маркетинга (применяем в текстах «Диасофт»)

**1. Outcome-first.** Сначала бизнес-результат («закрытие биржевого дня до 12:00», «реестр за 2 часа вместо 3 дней»), потом механизм. Покупатель в финсекторе покупает меньше ошибок, меньше операционного риска, соблюдение сроков регулятора — не «микросервисы».

**2. Четыре слоя сообщения** (все должны присутствовать и не противоречить друг другу):
- результат — что меняется в бизнесе;
- задача — что заказчик хотел сделать (критерии выбора, требования);
- механизм — как работает, на нужной высоте (продукт, интеграции, архитектура — одно-два предложения);
- доказательство и границы — цифры, регуляторные проверки, статус, что не входит в проект.

**3. Complexity budget.** Техническая деталь остается в тексте, только если она снижает воспринимаемый риск покупателя (импортонезависимая СУБД, электронный документооборот с НРД, микросервисы = независимое обновление). Иначе — вырезать.

**4. Три перевода одного смысла.** Один и тот же факт формулируется для CEO/бизнеса (результат, сроки), для операций (процессы, отчетность), для ИТ (архитектура, интеграции). В релизе — по одному предложению на каждую аудиторию; в лендинге — по блоку.

**5. Proof-first / claims library.** Каждое утверждение об эффекте имеет источник: бриф заказчика, акт приемки, рейтинг, отчетность. Формулировки, прошедшие согласование, переиспользуем дословно — не переписываем «для свежести», чтобы не порождать новых согласований.

**6. Регуляторный триггер как инфоповод.** Указания ЦБ, таксономии, сроки вступления — законный повод для новости и главный магнит для отраслевых СМИ. Формула: «с [дата] участники рынка должны …; решение «Диасофт» уже поддерживает …». Всегда — точная ссылка и проверка юристами.

**7. Не скрывать статус и границы.** «Опытно-промышленная эксплуатация», «переход в промышленную эксплуатацию запланирован на …», «сервис закрывает переводы между собственными счетами клиента» — доверие растет, когда границы названы явно.

**8. Партнерский баланс.** В совместных релизах заказчик — герой, вендор — инструмент результата. Логотипы, цитаты, цифры заказчика — только согласованные.

**9. Один релиз — несколько носителей.** Из релиза делаем: новость на сайте, пост в Telegram/VK, письмо журналисту, слайд в продажах, обновление кейса на лендинге. Смысл и цифры одинаковы везде; меняется только длина и форма.

**10. Тон отрасли.** Финансовый B2B читает сдержанно: точные глаголы, короткие предложения, никакой эмоции сверх «отметил». Убедительность — из фактов и структуры, не из прилагательных.

## C. Быстрая самооценка готового текста (0–2 балла за пункт)

| Критерий | 0 | 1 | 2 |
|---|---|---|---|
| Результат в первой трети | нет | есть, но без цифры | цифра + срок |
| Заголовок | двоеточие/цифра/длинный | норм, но статус не совпадает | одно предложение, статус верный |
| Цитаты | дублируют текст | разные, но взаимозаменяемы | у каждой своя функция |
| Факты | есть выдуманные | все из брифа, нет пометок | все из брифа + `[уточнить]` где пусто |
| Тон | реклама | нейтрально, но тяжело | нейтрально, читается легко |

Меньше 8 баллов — переписать перед выдачей.
