# Шаблоны форматов

Блок без факта в брифе не пиши. `[уточнить: ...]` в теле — только если без слота рушится предложение (дата, продукт, цифра, которую предложение уже обещает). Цитату без тезиса спикера удали целиком. Роль «Диасофт» без перечня работ не заменяй фразой «это решение компании»: оставь одну фразу технологической базы, если она есть в брифе. В совместном релизе для СМИ три строки-заглушки в конце остаются всегда: справки сторон и контакты.

## 1. Совместный пресс-релиз для СМИ

```
# [Заказчик] [переводит / запустил в опытно-промышленную эксплуатацию / автоматизировал] [процесс] [с помощью решений / вместе с / на решениях] «Диасофт»

[Заказчик] и компания «Диасофт» [дата] [запустили в опытно-промышленную эксплуатацию / завершили проект] [что]. Для этой задачи выбран [продукт так, как он назван в брифе]. Решение [охватывает / автоматизирует] [2–3 главных процесса] и [эффект, если он есть в брифе].

Проект стал [этапом развития платформы заказчика / ответом на регуляторные требования]. [Нейтрально о прошлом, только если бриф это дает: собственная система заменяется промышленным решением.] Ключевыми требованиями проекта стали [требования из брифа].

Решение автоматизирует [перечень процессов]. В рамках проекта [только выполненные работы из брифа: ЭДО, проверка процессов, миграция данных].

«[Тезис заказчика из брифа. Один показатель — здесь и больше нигде.]», – отметил(а) [Имя Фамилия], [должность из брифа] [организация].

Специалисты «Диасофт» [развернули, настроили, миграция, интеграция, консультации — по брифу]. Комплекс развернут на [одна фраза технологической базы из белого списка].

«[Значение для заказчика или рынка]. [Подход]. [Что меняется дальше — если есть в брифе.]», – отметил [Имя Фамилия], руководитель продуктового направления «[X]» компании «Диасофт».

[Дополнительный сервис — отдельный абзац. Регуляторная ссылка с датой и номером. Связка систем — здесь.]

«[2–3 предложения только об этом сервисе]», – отметил [Имя Фамилия], руководитель продуктового направления «[Y]» компании «Диасофт».

[Статус: сопровождение; переход в промышленную эксплуатацию — срок и условие из брифа.]

[Заказчик] и «Диасофт» планируют продолжить [развитие решения / сотрудничество из брифа].

---
О компании [Заказчик] — блок предоставляет заказчик
О компании «Диасофт» — блок предоставляет «Диасофт»
Контакты для СМИ: пресс-служба заказчика; pr@diasoft.ru
```

В текст для читателя не попадают слова «стайлгайд», «бриф», «белый список». Справку о «Диасофт» из стайлгайда подставляй только после сверки цифр; до сверки оставь строку «блок предоставляет «Диасофт»».

Порядок трех цитат совпадает с порядком блоков: заказчик → основной продукт → дополнительный сервис.

## 2. Новость на сайте «Диасофт»

Тот же каркас, что у релиза для СМИ. Справки «О компании» и контакты не добавляй. Финальная строка: «Для получения дополнительной информации заполните форму обратной связи». Допустимы две цитаты. Заголовок может назвать продукт: «... благодаря продукту «Диасофт»».

## 3. Продуктовая новость

Пиши, когда новость — о возможности продукта, а не о проекте заказчика.

```
# «Диасофт» [реализовал / расширил / добавил] [что] в [продукт]

Компания «Диасофт» расширила возможности [«Продукт» (Digital Q.X) — имя из брифа] [для кого], реализовав [что]. Новая функциональность [соответствует требованиям Банка России (указание от ДД.ММ.ГГГГ №...), вступающим в силу с ... / закрывает задачу ...].

[Что это дает клиенту — только из брифа: срок, единая точка ответственности, периметр процесса.]

[Продукт] закрывает [процесс], включая:
- ...;
- ...;
- ....

«[Как устроена возможность и как ее будут развивать — из брифа]», – отметил [Имя Фамилия], руководитель продуктового направления «[X]» компании «Диасофт».

[Итог одной фразой: адаптация под требования, которые уже названы.] Для получения дополнительной информации заполните форму обратной связи.
```

## 4. Экспертная новость

```
# «Диасофт» рассказал о [тема]

[Дата] на [мероприятие] обсудили [повестка]. На мероприятии выступил [Имя Фамилия], [должность] компании «Диасофт». Он рассказал, [о чем — по тезисам брифа].

[Тезис 1 — задача рынка.] [Тезис 2 — что потребуется участникам.] [Тезис 3 — требования к технологиям.]

«[Позиция спикера, 2–3 предложения из его тезисов]», – отметил [Имя Фамилия].

«Диасофт» развивает решение [«Продукт» (Digital Q.X)], помогая участникам рынка [что делает продукт по брифу]. Об ИТ-решениях и трендах рынка эксперты компании рассказывают на отраслевых мероприятиях.
```

Продукт в финале — один мостик. Прямой призыв купить в экспертную новость не ставь.

## 5. Кейс

Объем 600–1000 слов. Порядок: заказчик и контекст → задача через требования → решение (продукты, архитектура, интеграции) → ход проекта (этапы, сроки, роли) → результаты → цитаты → планы.

Таблицу «было / стало» строй только по парам из брифа. У каждого результата есть единица измерения и период. Пару без второй колонки в брифе в таблицу не добавляй: оставь одну подтвержденную величину в тексте.

## 6. Лендинг-блок продукта

- H1: что продукт делает и для кого, до 70 знаков, без двоеточия.
- Подзаголовок: главный результат и доказательство из брифа (кейс, рейтинг, число клиентов).
- 3–5 карточек «задача → как закрывает продукт». Каждая задача — требование покупателя.
- Блок «Соответствие требованиям»: акты с номерами из брифа.
- Блок «Технологии»: только пункты белого списка, которые есть в брифе.
- Доказательство: логотипы и цитаты согласованных заказчиков.
- CTA: «Запросить демонстрацию» или «Получить консультацию».

На лендинге три аудитории разведи по блокам: руководитель видит результат, операции — процессы, ИТ — архитектуру и интеграции.

## 7. Карточка для продаж

Один экран. Факты те же, что в релизе или брифе; новых цифр нет.

```
# [Продукт]: [результат для кого]

Для кого: [роль покупателя из брифа]
Задача: [требование]
Результат: [одна величина из брифа или качественный результат без новой цифры]
Как устроено: [1–2 предложения из белого списка]
Доказательство: [кейс, статус или указание — из брифа]
Граница: [статус и что остается за периметром]
Дальше: Запросить демонстрацию / Получить консультацию
```

## 8. Пост для Telegram / VK

3–6 коротких абзацев уже согласованного релиза: факт → главный результат → одна сокращенная цитата → ссылка. Новую цифру, новый эпитет и новый тезис спикера в пост не добавляй. Эмодзи-ряд не ставь. Один маркер в начале допустим, если так оформлен канал. Хэштеги — только принятые в канале.

## 9. Сопроводительное письмо журналисту

Тема: `[Заказчик] и «Диасофт»: [суть в 6–8 словах]`.

Тело: два предложения о новости; одно — почему это сейчас важно аудитории издания (срок регулятора или отраслевой повод из брифа); предложение комментария спикера; вложение или ссылка. Подпись пресс-службы. В письме нет факта, которого нет в релизе.
