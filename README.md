# Work

Личный контур руководителя продуктового направления: проекты запуска у клиентов, бэклог развития, сроки и напоминания.

- [Техническое задание](docs/TZ.md) — сценарии, экраны, поля, формат почты и Telegram, подсветка за 14 дней, приёмка.
- [Архитектура](docs/ARCHITECTURE.md) — сервис, модель данных, разбор сообщений, оповещения, развёртывание.

Общая шапка фильтрует проекты и бэклог по команде, продукту, клиенту и контрольной дате. Оповещения уходят в Telegram. Почта и Telegram принимаются как каналы входа: сырое сообщение сохраняется, неразобранное остаётся во входящих.

## Запуск

База, Docker и PostgreSQL не нужны. Нужна одна программа: Node.js 22.5 или новее. Данные записываются в файл `data/work.db` рядом с кодом.

На странице репозитория по умолчанию открыта ветка `main`. Там приложения ещё нет. Код лежит в ветке `cursor/product-control-spec-afd9`.

### 1. Установить Node.js

Скачайте установщик Node.js 22 с [nodejs.org](https://nodejs.org/) и установите его как обычную программу. Закройте терминал, если он был открыт, и откройте новый. Проверка:

```bash
node -v
```

Должно быть `v22.5` или выше, например `v22.14.0`. Если команда не находится или версия меньше, дальше идти рано: сначала доустановите Node и откройте терминал заново.

### 2. Скачать эту ветку

Без Git: откройте [ветку cursor/product-control-spec-afd9](https://github.com/kkokurin799/Work/tree/cursor/product-control-spec-afd9), нажмите Code → Download ZIP и распакуйте архив.

С Git:

```bash
git clone https://github.com/kkokurin799/Work.git
cd Work
git checkout cursor/product-control-spec-afd9
```

Дальше все команды выполняются в распакованной папке. В проводнике Windows можно открыть эту папку и набрать `cmd` в адресной строке: терминал откроется сразу в нужном месте.

### 3. Задать почту и пароль для входа

Скопируйте файл `.env.example` и назовите копию `.env`. Точка в начале имени обязательна. В проводнике: скопировать файл и переименовать. В терминале:

```bash
cp .env.example .env
```

В Windows-командной строке вместо этого: `copy .env.example .env`.

Откройте `.env` блокнотом и поменяйте только три строки:

- `SESSION_SECRET` — любая длинная случайная фраза. Её не нужно запоминать, это не пароль входа.
- `OWNER_EMAIL` — почта, которой будете входить.
- `OWNER_PASSWORD` — пароль для этой почты.

Строки Telegram и почты оставьте пустыми.

### 4. Запустить

```bash
npm install
npm run dev
```

`npm install` нужен один раз. `npm run dev` запускает сайт и не должен завершаться: окно терминала остаётся открытым. Когда появится строка `Local: http://localhost:3000`, откройте этот адрес в браузере. Войдите почтой и паролем из `.env`.

Остановка: в том же терминале нажмите Ctrl+C.

Первый запуск создаёт `data/work.db` и пользователя. Пароль записывается только тогда. Если такая почта уже есть в файле, правка `OWNER_PASSWORD` её не меняет: удалите `data/work.db` и запустите снова, чтобы пользователь создался заново.

`SQLITE_PATH` можно не задавать. Копия базы пишется в `backups/work-ГГГГ-ММ-ДД.db` раз в сутки, хранятся 14 последних файлов.

Срез Telegram включается переменными `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и `TELEGRAM_OWNER_USER_ID`. Webhook: `POST /api/telegram/webhook`. Для него нужен публичный HTTPS-адрес, локального `npm run dev` недостаточно. Срез почты — `IMAP_HOST`, `IMAP_USER`, `IMAP_PASSWORD` и `IMAP_ALLOWED_FROM`. Пока переменные пустые, реестр работает без бота и без ящика.
